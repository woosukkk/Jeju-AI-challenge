## P0-01 — 필수 데이터부터 해결

사용자는 센터 방문·원본 직접 접근이 어렵다고 했다. 현 후보 `2-03 기업정보`의 **명세서만 있고 실제 관측 테이블은 없다**. 원본 반출 불가라는 이유만으로 모든 활용이 불가능하다고 단정하지 말고, 허용된 센터 내 사용·승인된 가공본·원격 접근 가능 여부를 확인한다. 제공기관에 메시지를 보내는 일은 사용자에게 명시적으로 요청받았을 때 수행한다.

다음 개발자가 할 일:

- [ ] 실제 사용 가능한 파일 경로 또는 공식 다운로드/API 경로 확인. 다른 제주데이터허브 공개 자료를 대안으로 조사한다면 실제 목록·필드·제공 조건을 먼저 확인하고 데이터셋명을 확정한다.
- [ ] 데이터셋명·기관·기준일·취득 경로·관측 단위·원본 행 수·검색 필수 열을 기록한다. 없는 생산품·사업자번호를 추정해 채우지 않는다.
- [ ] PC 사용/로컬 저장, 가공본 반출, Git/ZIP 재배포, LLM/API 외부 전송 허용 범위를 **각각** 기록한다. 현재 출처 후보를 사용할 수 없으면 필수 데이터 활용 방법을 재설계하고 근거를 적는다.
- [ ] `ingest.py`의 열 대응을 실제 파일과 대조하고 승인된 별도 DB로 반입한다. 결측·중복·제외 행 수·기준일·SHA-256을 기록한다.
- [ ] 실제 기업 몇 곳의 생산품·지역·출처가 원본과 맞는지 대조한다. 승인되지 않은 행·식별정보는 문서나 스크린샷에 노출하지 않는다.
- [ ] [DATA_USAGE.md](DATA_USAGE.md), [PROGRESS.md](PROGRESS.md), [RESULTS.md](RESULTS.md)에 실제 수행 결과를 반영한다.

완료 기준: **승인된 실제 제주 필수 데이터 1종 이상을 사용해 검색→결과 근거까지 실행**하고, 평가자가 같은 데이터에 접근하거나 허용된 방식으로 재현할 수 있다. 데모·국세청만 사용한 실행은 완료가 아니다. 파일 반입 기능이 있다는 것과 실제 반입 성공을 구분한다.

## P0-02 — 주력 LLM 실검증

코드에는 두 공급자 연결이 있지만 실제 호출은 없다. 사용자가 Gemini 또는 OpenAI를 사용할 예정이며, 우선 **한 공급자**로 전체 흐름을 확인한다. 기본 모델 문자열은 계정의 사용 가능 여부나 호환성의 증거가 아니다.

- [ ] 로컬 `.env`에 공급자·키·실제로 사용 가능한 `LLM_MODEL` 설정. 공식 문서/계정에서 도구 호출·요청 파라미터·JSON 응답 호환성을 확인한다.
- [ ] 가상 자료 또는 전송 허용 자료로 검색 도구 호출→조회 ID 선택→근거 표시까지 실호출한다. 오류가 나면 `agent.py`, `config.py`, `tests/test_agent.py`를 함께 수정한다.
- [ ] 텍스트 견적 추출→사용자 수정·확인→저장→비교를 실행한다. 미기재 값 null, 잘못된 JSON, 요청 실패를 확인한다.
- [ ] 실제 모델 ID·시각·성공/실패·소요 시간·확인 가능한 사용량을 키/원문 없이 기록한다. 모의 테스트에 실제 공급자에서 확인한 응답 형태를 반영한다.
- [ ] 외부 전송 false일 때 네트워크 호출이 없는 회귀를 유지한다. 자동 재시도 없이 오류와 수동 대안을 표시한다.

완료 기준: 주력 공급자에서 **검색 Agent와 견적 추출을 각각 실제로 실행**하고 화면까지 확인한다. 다른 공급자는 검증 전까지 미검증으로 남긴다. LLM이 반환한 확인 질문은 현재 표시만 되며 대화 상태를 이어가는 다중 턴 Agent는 아니다.

완료 기준: 제출 형식으로 렌더링한 최종 문서가 15쪽 이내이고, 다른 참가팀이 기획서만 읽어도 대상·사용 흐름·Agent 역할·실제 활용 데이터를 이해할 수 있다.

- [ ] 최종 코드에서 pytest·ty·pip check를 실행하고 실제 결과를 기록한다.

## P1-01 — 화면 흐름·입력 보완

변경 전에 데모로 재현하고 필요한 범위만 수정한다. 아래는 **점검 과제**이며 모두 재현된 버그라는 뜻은 아니다.

- [ ] 기존 업체 견적 저장→후보 견적 작성에서 업체 선택·폼 값·원문 확인 체크가 어떻게 유지되는지 확인한다. 사용자가 이전 업체 값/확정을 새 업체에 그대로 적용하지 않도록 안내·초기화/재확인 흐름을 정한다.
- [ ] 새 견적 저장 후 비교 대상에 포함시키는 절차와 기준 업체 선택이 도민에게 명확한지 확인한다. 현재 비교 대상은 별도 multiselect다.
- [ ] 메뉴 이동·후보 제거·저장/수정/삭제·기준 견적 삭제·추출 후 재편집을 점검하고 `test_app.py`에 핵심 회귀를 남긴다.
- [ ] 조건이 다른 견적의 차액 제외 이유, 빈 배송비/세금, 만료·최소 주문 미달이 사용자에게 읽히는지 확인한다.
- [ ] 검색의 별도 입력은 현재 품목 문장·지역·업종뿐이다. 기획의 규격·수량·납기는 견적/문의에서 입력한다. 앞 단계에서 수집할지 기획 표현을 줄일지 결정해 화면과 문서를 맞춘다.

완료 기준: 신규와 기존 사업자의 대표 작업을 제삼자가 따라 하고, 후보 선택→견적→비교→문의/보고서를 개발자의 구두 보충 없이 완료한다. 자동 테스트 통과와 실제 도민 사용성 측정은 따로 기록한다.

## P1-02 — 실제 검색 품질·성능

- [ ] 실제 생산품을 근거로 대표 질의 목록을 만들고 정답/후보 판정 기준을 수동으로 적는다. 검색 불가·지역 제외·정보 부족 사례도 포함한다.
- [ ] 기본 키워드와 Agent 검색을 구분해 적합 후보·누락·과도한 확장·소요 시간을 기록한다. 개선은 관측한 실패 사례부터 한다.
- [ ] 실제 자료 규모에서 파일 반입·DB 로딩·후보 검색을 측정한다. 현재 기본 검색은 파싱된 기업 목록을 순회한다.
- [ ] 의미 검색을 사용할 경우 검색할 때마다 필터된 기업 문서를 인코딩하는 현재 구조를 먼저 측정한다. 모델 객체 캐시만으로 문서 벡터가 재사용되는 것은 아니다.

완료 기준: 실제 자료/질의로 재현 가능한 측정 기록과 한계가 있고, 미측정 성능 수치를 기획서에 넣지 않는다.

## P1-03 — 근거 표시와 실제 구현 정합성

- [ ] 별도 제품정보 확인일 필드는 현재 없다. 원본 기준일을 제품 현재 확인일로 소개하지 않는다. 필드를 구현할 필요가 없다면 문서 표현을 유지 범위에 맞춘다.
- [ ] 국세청 `end_dt`는 저장하지만 기본 상세 UI에서 폐업일은 별도 표시하지 않는다. 실제 응답 확인 뒤 필요한 표시만 추가한다.
- [ ] 문의 초안은 현재 고정 양식이다. LLM이 작성·발송한다고 설명하지 않는다.
- [ ] 비교 보고서는 견적 입력값·기업 출처 중심이다. Agent 모델/실행 환경/실제 데이터 해시는 검증 기록에 따로 남기고, 검색 결과 보고서까지 구현됐다고 설명하지 않는다.
- [ ] 현 인기 집계는 이 PC의 로컬 이벤트다. 임의 초기 인기 수치·외부 검색 순위·품질 점수로 바꾸지 않는다.

완료 기준: 화면·PRODUCT·MANUAL·RESULTS·기획서의 구현/검증 주장이 서로 일치한다.

## P1-04 / P2 — 이후 작업

디자인은 레퍼런스 수령 후 기존 호출부·세션 상태·회귀 테스트를 유지하며 적용한다. 레퍼런스가 없다고 기능·제출 문서 작업까지 멈출 필요는 없다.

의미 검색은 실모델을 설치·검증하고 필요하면 문서 벡터를 데이터 해시에 묶어 재사용한다. 별도 벡터 DB·Docker·다중 Agent·서비스 분리부터 추가하지 않는다. 둘째 LLM 공급자, OCR, 다품목 견적, 로그인/다중 사용자, 외부 자동 연락은 이번 제출의 필수 범위로 확대하지 않는다. 필요가 확인되거나 사용자가 요청하면 범위·테스트·문서를 함께 갱신한다.
