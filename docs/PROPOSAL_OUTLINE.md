# 15쪽 이내 기획서 구성안 — 거래잇수다

문서 초안용 구성이다. 실데이터 성능·효과 수치는 아직 측정하지 않았으며 아래 검증 자리에 실제 결과를 넣어 완성한다.

| 쪽 | 제출 요구와 내용 |
|---|---|
| 1 | 서비스 제안: 제주 사업자의 거래처 탐색·견적 비교·문의 준비를 더 쉽게 |
| 2 | 대상·문제: 신규 창업자와 기존 소상공인의 작업 과정, 확인이 필요한 사용자 가설 |
| 3 | 구현 목표: 탐색 시간·동일 조건 비교 완료율·출처 확인율의 측정 계획 |
| 4 | 이용 시나리오: 신규 후보 탐색과 기존 거래처 기준 비교 |
| 5 | 필수 데이터: 제주 기업정보의 실제 반입 범위·기준일·열·행 수·허가 증빙 (확보 필요) |
| 6 | 데이터 가공·보조 API: 필드 대응·해시·결측·중복·국세청 상태조회 |
| 7 | Agent 역할·자율 범위: 요구 해석→검색 도구 최대 2회→근거 ID 선택→확인 질문 |
| 8 | Workflow·모델·도구: Gemini/OpenAI, SQLite, 선택 CPU 임베딩, 견적 추출·확정 |
| 9 | 비교 결과 신뢰성: Decimal 계산·동등 조건·미확인 값·출처·유효기간 |
| 10 | 화면·편의성: 후보 선택→견적→비교표→문의 초안·HTML/CSV 보고서 |
| 11 | 관심·최신성: 실제 로컬 이벤트와 사업자 상태 캐시, 자동화의 범위·한계 |
| 12 | 개발·탑재 계획: Python/Streamlit, Windows 설치, 키 분리, 최소 PC 사전 점검 |
| 13 | 구현·검증 결과: 자동 테스트와 실제 데이터 실행을 구분, 미검증 항목 명시 |
| 14 | 비용·개인정보·라이선스·한계: API 요청 상한, 원본 이용조건, 담당자 확인 |
| 15 | 재현·제출물: 코드·실행 매뉴얼·데이터 명세·결과 설명·검증 기록 위치 |
