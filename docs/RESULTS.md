# 결과 설명과 검증 범위

## 사용자가 더 쉽게 끝내는 일

기업 목록을 직접 뒤져 후보를 옮겨 적고, 조건이 다른 견적을 계산기로 맞추고, 다시 문의 문장을 작성하던 과정을 하나의 화면 흐름으로 연결했다. 신규 창업자는 후보 탐색부터, 기존 사업자는 기존 견적을 기준으로 비교부터 시작할 수 있다. 생산품 검색은 공급 가능성의 확인을 대신하지 않는다.

## 구현한 Agent와 재현 원리

`run_agent`는 제한된 도구 세 가지(업종 분류 확인 `list_categories`, 조건 검색 `search_companies`, 지역별 집계 `count_by_region`)만 자율 호출한다. 사용자의 지역·업종 필터는 도구 호출 과정에서 고정한다. 요청은 최대 6번, 도구 호출은 최대 5번이며 한도에 닿으면 도구 없이 결과를 정리한다. 조회 결과에 포함된 ID만 선택할 수 있다. 요약에 도구 결과에 없는 숫자가 있으면 요약을 숨긴다. 존재하지 않는 업체를 반환하면 오류 처리한다. AI의 자유 서술을 가격·신용·공급 가능성의 근거로 사용하지 않는다. 수행 기록에는 도구명과 결과 ID가 표시된다. 키 미설정 모드에서는 이 작업을 AI가 수행했다고 표시하지 않는다.

견적 추출은 미확인 값을 null로 유지하는 초안이다. 사용자 확정 이후에도 단가·세금·배송비·추가 비용이 확인되어야 총액을 계산한다. Decimal로 계산하며 총액은 소수 셋째 자리에서 반올림해 둘째 자리까지 표시한다. 기준 대비 차액은 동등한 품목·규격·수량·단위·통화일 때만 계산한다. 최소주문 미달·견적 만료·미래 발행일도 판정한다. 납기·최소주문·유효기간이 없으면 별도 확인 항목으로 남는다. 업체별 다른 반올림·결제수수료·할인 조건은 명시적으로 입력된 범위만 계산한다.

CSV·HTML 보고서에 입력값·출처·제한을 남긴다. HTML은 입력을 이스케이프하고 CSV는 수식 주입을 막는다. 사용자 확인 견적이 사실이라는 외부 인증은 제공하지 않는다. 원본 파일 해시와 소스 코드·동일 입력으로 계산 결과를 재현할 수 있으며 LLM의 후보 선택은 모델·공급자 변경에 따라 달라질 수 있다.

## 실제 데이터 검색 측정 (2026-11-17~18)

데이터: 제주데이터허브 「제주특별자치도 상가(상권) 정보」 57,347곳. 개발 PC(Windows 11)에서 `scripts/measure_search.py`로 측정했다. DB 읽기 0.8~1.1초.

판정 방법: 질의마다 '이 말이 업종 또는 생산품 칸에 있으면 적합'인 단어를 실행 전에 정하고, 상위 5곳 중 적합한 곳의 수를 셌다. 사람이 하나씩 판정한 것이 아니라 자동 근사치다. 질의 12개는 개발자가 정한 것으로 실제 도민 질의 표본이 아니다.

| 질의 | 지역 | 키워드 검색 | Agent: Gemini gemini-3.5-flash-lite | Agent: OpenAI gpt-5.4-mini |
|---|---|---|---|---|
| 가게 간판을 새로 달고 싶어요 | 전체 | 5/5 | 5/5 (8.1초) | 5/5 (7.8초) |
| 가게 간판을 새로 달고 싶어요 | 서귀포시 | 5/5 | 5/5 (5.4초) | 5/5 (4.8초) |
| 택배 박스 포장재가 필요해요 | 전체 | 5/5 | 5/5 (5.1초) | 5/5 (5.4초) |
| 택배 박스 포장재가 필요해요 | 제주시 이도1동 | 0곳 | 0곳, 다른 지역 업소 수 안내 (9.2초) | 0곳, 다른 업종 재검색 (9.4초) |
| 명함과 전단지를 인쇄하고 싶어요 | 전체 | 5/5 | 5/5 (9.0초) | 5/5 (5.7초) |
| 가게 로고 디자인을 맡기고 싶어요 | 전체 | 5/5 | 5/5 (13.0초, 요약 숨김) | 5/5 (5.1초) |

| 페인트와 건축 자재를 사고 싶어요 | 전체 | 5/5 | 5/5 (7.1초) | 5/5 (6.1초) |
| 식당 업소용 냉장고 수리 | 전체 | 5/5 (실제로는 2곳만 맞음) | 0곳, 후보를 고르지 않음 (6.9초) | 5/5, 모두 가전제품 수리 (5.5초) |
| 반도체 웨이퍼 장비 | 전체 | 0곳 (정답) | 0곳 (정답, 15.3초) | 0곳 (정답, 8.5초) |

- OpenAI는 2026-11-18, Gemini는 2026-11-17에 쟀다. OpenAI는 12개 모두 성공(질의당 4.8~9.4초, 2초 간격, 429 없음).
- Gemini Agent는 질의당 4.9~15.3초 걸렸다. 키워드 검색보다 10배 이상 느리지만, 분류 확인(`list_categories`)과 0곳일 때 지역별 집계·재검색을 스스로 했다.
- 처음 연속 실행에서는 다섯 질의 뒤 Gemini 무료 키가 429(호출 한도)를 돌려줬다. 나머지 일곱 질의는 30초씩 쉬며 다시 쟀다. 429일 때 앱은 키워드 검색으로 이어간다.
- Gemini 측정은 후보 번호(A, B…) 도입 전 코드로 했다. '로고 디자인'에서 Gemini 요약이 숨겨졌는데, 같은 원인(검색이 돌려준 업체 수 '5곳'을 근거 없는 숫자로 본 것)으로 보이며 2026-11-18에 업체 수를 허용하도록 고쳤다. Gemini로는 고친 뒤 다시 재지 않았다.
- '식당 냉장고 수리'에서 Gemini Agent는 수리 업소를 두 번 검색한 뒤 맞는 후보가 없다고 판단해 아무것도 고르지 않았고, OpenAI Agent는 '가전제품 수리' 업종으로 좁혀 5곳 모두 가전제품 수리점을 골랐다. 키워드 검색은 모터사이클·자동차 수리까지 섞여 실제로 맞는 곳이 2곳이었다. Agent가 업종 분류를 확인하는 효과가 드러난 사례다.
- OpenAI 첫 실호출에서 모델이 24자 업체 ID를 한 글자 틀리게 옮겨 적어 결과 전체가 차단되는 일이 7회 중 2회 있었다. 검색 결과에 A, B, C… 짧은 후보 번호를 붙인 뒤 5회 모두 성공했다.
- 키워드 검색은 질의당 0.02~0.9초(전체 지역 0.5~0.9초).
- 처음 측정에서 3가지 오검색이 나와 고쳤다: ① '박스'처럼 두 글자 상호(가방 가게)가 업체명 입력으로 잡혀 맨 위에 옴 ② '식당 냉장고 수리'에서 '식당'(사용자 자신의 가게) 때문에 음식점이 후보가 됨 ③ '반도체 웨이퍼 장비'에서 '장비'만으로 운송장비 대여점이 나옴. 고치기 전 판정은 각각 4/5, 1/5, 오답(5곳)이었다.
- '식당 업소용 냉장고 수리'는 자동 판정으로 5/5지만 직접 보면 가전·가정용품 수리 2곳만 맞고 모터사이클·자동차 수리 3곳은 아니다. 데이터에 '냉장고' 수리 업종이 따로 없어 '수리'로만 찾기 때문이다.
- '택배 박스 포장재'를 제주시 이도1동에서 찾으면 0곳이다. Agent는 `count_by_region`으로 다른 지역의 업소 수를 세어 요약에 알렸다.

## AI 호출 비용 (2026-11-18, OpenAI gpt-5.4-mini)

실제 호출의 usage(입력·출력 토큰)를 세고, 표준 요금(입력 100만 토큰당 0.75달러, 출력 4.50달러, [공식 요금표](https://developers.openai.com/api/docs/pricing))으로 계산했다. 캐시 할인은 넣지 않았다.

| 기능 | 요청 수 | 입력 토큰 | 출력 토큰 | 비용(달러) |
|---|---|---|---|---|
| 검색 Agent (12개 질의 평균) | 3.4 | 3,985 | 221 | 약 0.004 (최대 0.008) |
| 문의 질문 (업체 1곳) | 1 | 338 | 150 | 약 0.001 |
| 견적 추출 (가상 견적 1건) | 1 | 826 | 101 | 약 0.001 |
| 비교 해설 (견적 3건) | 1 | 532 | 364 | 약 0.002 |

6단계를 한 번 끝까지 쓰면(검색 1회, 문의 3곳, 추출 1건, 해설 1회) 약 0.01달러다. 측정: `scripts/measure_search.py --agent`가 질의별 요청·토큰을 `outputs/`에 남긴다.

## 화면 전체 실행 (2026-11-18, OpenAI)

실제 데이터와 `gpt-5.4-mini`로 1~6단계를 브라우저에서 끝까지 진행했다. 기존 거래처(가상) + 후보 2곳 → AI 검색(요약·단계 표시) → 문의 초안 3곳(AI 확인 질문 5개씩) → 가상 견적 텍스트 AI 추출 → 저장 2건 → 비교표(765,000원 vs 800,000원, 차액 -35,000원) → AI 해설. 추출은 설치비 50,000원(부가세 포함)을 비워 두어 사용자가 채웠고, 규격을 '1200x600'으로 적어 요청('1200x600 LED')과 맞춰야 했다. 화면 확인 뒤 시험 견적·관심 기록은 DB에서 지웠다. 이 실행에서 Agent 요약이 화면에 없는 후보 번호(A, B…)를 쓰는 것을 발견해 상호로 부르게 고쳤다.

## 검증의 구분

- 자동 검증: 합성 기업 자료, 반입 원자성, 필수값·형식, 조건 필터, 실제 데이터에서 나온 오검색 재현, 모의 LLM 도구 호출과 전송 차단, 모의 국세청 응답·캐시, Decimal 계산, 관심 중복·기간, 다운로드 안전성, 제출 ZIP 금지 파일 검사, 6단계 화면 흐름. `pytest -q` 45 passed.
- 실제 실행: 상가 데이터 반입·검색(위 표), Gemini·OpenAI 실호출(검색 Agent·비교 해설·문의 질문·견적 추출, 호출당 약 2~9초), 제출 ZIP을 새 폴더에 풀어 설치→반입→실행→검색. 모두 개발 PC에서 했다.
- 국세청 상태조회: 공개 법인 사업자번호로 실조회 성공(0.56초, 계속사업자). 상가 데이터에는 사업자번호가 없다.
- 미검증: 선택 임베딩 모델, 센터 최소 사양 PC 성능, 도민 사용성 실험. 견적은 모두 가상 예시다.

가상 데모 데이터와 모의 API 테스트 통과를 실제 필수 데이터 활용이나 외부 API 정상 작동으로 표현하지 않는다. 무료 Gemini 키로 Agent를 연달아 실행하면 429(호출 한도)가 날 수 있으며, 이때 앱은 키워드 검색으로 이어간다.
