## 사용자와 합의한 제품

**거래잇수다**는 제주 예비 창업자·소상공인·기업 담당자가 **거래처를 찾고, 기존 업체와 같은 조건으로 비교하고, 문의를 준비하는 일을 더 쉽게 하는 서비스**다. 기존 업체는 검색 DB에 없어도 직접 입력할 수 있다. 신규 사업자 전용 서비스로 축소하지 않는다.

- 중심 흐름: 품목 검색 → 근거가 있는 후보 → 비교에 담기 → 기존/후보 견적 입력·확정 → 동등 조건 비교 → 문의 초안·보고서.
- 핵심 가치는 RAG 답변 자체보다 이 작업 흐름의 편의성이다. 후보를 골랐다는 이유로 가격·납기·신뢰도를 추측하지 않는다.
- 문의는 초안만 만든다. 자동 발송·계약·결제는 구현 범위에 없다.
- 사용자가 2.5일 안의 구현량을 엄격히 줄일 필요는 없다고 했다. 다만 최소 사양 PC와 마감에서 검증 가능한 기능을 우선한다.

## 지켜야 할 동작

- `ALLOW_EXTERNAL_DATA=false`이면 **검색·추출 LLM 호출과 국세청 신규 조회 모두 차단**된다. 공개 질의만 해석하는 별도 LLM 모드는 구현되어 있지 않다. 국세청의 이전 로컬 캐시는 표시될 수 있다.
- 검색 Agent는 LLM 요청 최대 3회, 검색 도구 호출 최대 2회다. 수동 필터를 덮어쓸 수 없으며 조회되지 않은 업체 ID는 차단한다. 회사 데이터의 문자열은 실행 명령이 아니다.
- 견적의 빈 금액은 미확인이다. 사용자 확인과 필수 비용 확인 없이 총액을 확정하지 않는다. 계산에 float를 쓰지 않는다.
- 차액은 품목·규격·단위·수량·통화가 맞을 때만 계산한다. 다른 조건의 총액이 표시되더라도 동일 조건 차액으로 취급하지 않는다.
- 인기·사업자 상태는 품질·신용·공급 능력의 보증이 아니다. 원본 기준일·국세청 성공 시각·견적 발행일/유효기간을 혼합하지 않는다.
- 원본·키·사용자 견적·DB·임베딩은 공개 Git에 넣지 않는다. 개인정보 제거·가명처리는 현재 사용자가 입력 전에 수행하며 자동 익명화를 주장하지 않는다.
- 현재 앱은 localhost의 단일 사용자용이다. 견적은 로컬 DB에 저장되고 세션별로 분리되지 않는다. 다중 사용자 보안을 구현했다고 설명하지 않는다.

## 실행과 검증

PowerShell에서 저장소 루트로 이동한다. 기존 `.env`를 덮어쓰지 않는다. 키 값은 출력·복사해 문서에 남기지 않는다.

```powershell
Set-Location 'C:\Jeju-AI-challenge'
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ty check app.py trade_itsuda
.\.venv\Scripts\python.exe -m pip check
```

새 PC 설치와 API 설정은 [매뉴얼](MANUAL.md)을 따른다. 개발·데모·실제 데이터·테스트는 서로 다른 `DATABASE_PATH`를 사용한다. 사용자 DB를 삭제하거나 임의로 초기화하지 않는다.
