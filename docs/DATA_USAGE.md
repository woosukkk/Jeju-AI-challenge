# 데이터 활용 명세와 반입 규칙

필수 원천 후보는 제주빅데이터센터 `2-03 기업정보`다. 기업명·업종·주요생산품·지역·사업자 식별번호·원본 기준일을 검색과 근거 연결에 사용한다. 첨부 명세에는 2020-07-31 기준, 원본 반출 불가·가공 형태 반출 가능이라고 적혀 있다. 실제 최신 원본·이용조건·개발/평가 접근 경로는 아직 확보하지 않았다.

공식 목록: https://jejudatahub.net/center/data

`2-01/2-02 거래처정보`는 명세상 2019년 기준이며 현재 관계·납품 품질의 증거로 쓰지 않는다. `2-08 휴폐업`은 2021년 기준이라 현재 상태 확인을 대체하지 않는다. 원본 거래 관계의 공개·외부 전송은 별도 승인이 필요하다.

국세청 사업자등록정보 진위확인 및 상태조회 서비스의 상태조회 기능을 보조 사용한다. https://www.data.go.kr/data/15081808/openapi.do

## 반입

CSV UTF-8/CP949 또는 XLSX의 평면 기업 테이블을 받는다. 명세서의 `2-03 기업정보` 시트 자체는 관측 테이블이 아니므로 반입하지 않는다. 실제 열의 의미를 확인하고 정규화한 필드를 사용한다. 회사 ID가 없으면 출처와 사업자번호/이름·지역으로 안정적인 내부 ID를 만든다.

최소 필드: `name`, `industry`, `products`, `region`, `source_name`, `source_date`. 영어 원천 열 `ent_nm`, `ksic10_biz_nm`, `main_products`, `address_emd`, `base_date`, `biz_num`, `ked_code`와 대응한다. 파일 반입 시 출처명·기준일을 사용자에게 확인받고, 외부 전송 허용 여부는 기본 거부다. 파일·정제본·DB·임베딩은 Git에 넣지 않는다.

## 재현과 표시

파일 해시·출처·반입 시각·행 수를 로컬 DB에 기록한다. 반입 오류 시 기존 자료를 변경하지 않는다. 검색 결과의 출처·원본 기준일·누락 조건을 표시한다. 합성 데모 업체는 모두 가상이고 도메인은 `.invalid`로 표시한다. 실제 기업·실제 인기·필수 데이터 활용 실적으로 표현하지 않는다.

명세·제공 샘플은 원본 반입을 대신하지 않는다. 재배포·외부 API 전송이 승인되지 않은 자료를 공개 GitHub·클라우드 RAG에 올리지 않는다.
