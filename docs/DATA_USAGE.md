## 열 대응

| 앱 필드 | 원천 열 | 쓰임 |
|---|---|---|
| 업체명 | 상호명 | 화면 표시, 기존 거래처 이름 검색 |
| 업종 | 상권업종중분류명 | 업종 필터, 검색(가중치 2) |
| 생산품 | 상권업종소분류명 + 표준산업분류명 | 검색(가중치 3), 근거 표시 |
| 지역 | 시군구명 + 행정동명 | 시 → 읍·면·동 선택, Agent의 지역별 집계 |
| 내부 ID | 출처명 + 상호명 + 지역 + 지번주소 | 같은 이름의 다른 업소 구분. 주소 자체는 DB에 저장하지 않는다 |

쓰지 않는 열: 상권업종대분류명, 시도명, 법정동명, 행정동코드, 법정동코드, 도로명주소, 신우편번호, 경도, 위도.

## 이용조건 확인 (2026-11-17)

| 범위 | 확인한 내용 | 판단 |
|---|---|---|
| 이 PC에서 사용·저장 | 원천 공공데이터포털 이용허락범위 "이용허락범위 제한 없음", 무료 | 사용 가능 |
| 제주데이터허브 사본 | 상세 페이지에 별도 이용 제한 문구 없음. 허브 이용약관 전문은 읽지 않았다 | 원천 조건을 따른다고 보되, 약관 전문은 미확인 |
| 외부 LLM 전송 | 공개 상호·업종·지역만 Agent 도구 결과로 보낸다 | 원천 조건상 제한 없음. 사용자 견적 원문은 별개이며 사용자가 판단한다 |
| GitHub 공개 저장소 | CSV·DB를 올리지 않는다 (`.gitignore`) | 저장소 용량·갱신 관리 때문에 넣지 않는다 |
| 제출 ZIP | `scripts/make_submission.py --data <CSV>`로 `data_source/jeju_store.csv`에 동봉할 수 있다 | 원천 조건상 가능. 최종 동봉 여부는 제출할 때 정한다 |

대회 측이 참가자에게 준 자료(데이터 목록 엑셀, `데이터명세서_kr.xlsx`)는 이 CSV와 다른 자료다. 그 자료는 DAKER 밖에 공유하지 않으며 Git·ZIP에 넣지 않는다.

## 처음 검토했던 후보

제주빅데이터센터 `2-03 기업정보`(기업명·업종·주요생산품·사업자번호)는 명세서만 있고 실제 기업 표를 받을 수 없었다(센터 방문 필요, 원본 반출 불가). 그래서 공개된 상가(상권) 정보로 바꿨다. `2-01/2-02 거래처정보`, `2-08 휴폐업`도 사용하지 않는다.

## 이 데이터로 할 수 없는 것

- '생산품' 칸은 상권업종 분류명이다. 실제 취급 품목·가격·공급 능력이 아니므로 화면에 "과거 기록이라 현재 공급 여부와 연락처는 업체에 확인"이라고 적는다.
- 사업자번호가 없어 국세청 상태조회와 연결할 수 없다. 이 데이터의 업소에는 국세청 조회를 쓰지 않는다.
- 2025-09-18 이후 폐업·개업은 반영되지 않는다.
- 제조업체·도매상보다 소매·음식점 위주라서, 원자재 공급처 검색에는 후보가 적거나 없을 수 있다(예: '반도체 웨이퍼 장비'는 0곳).

## 반입과 재현

- 화면: 데이터 관리 → CSV 선택 → 출처명·공통 기준일 입력 → 가져오기.
- 명령: `data_source\jeju_store.csv`에 두고 `import_data.bat` 실행(출처명·기준일 기본값 사용). 2026-11-17 확인: 화면 반입과 행 단위로 같은 결과, 약 4~10초.
- DB에는 파일 SHA-256·출처명·반입 시각·행 수를 기록한다. 반입 오류가 나면 기존 자료를 바꾸지 않는다.
- 합성 데모 4곳은 기능 시험용 가상 업체이며 실제 데이터 활용 실적으로 쓰지 않는다.
